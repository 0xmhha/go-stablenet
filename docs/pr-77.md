
[StableNet] 거버넌스 GasTip 복원 제안 시 트랜잭션 Pending Pool 정체 이슈 원인 분석

## 설명

## 배경
- StableNet에서는 거버넌스를 통해 gasTip 값을 동적으로 변경할 수 있음.
- 기본값은 27600 Gwei이며, 거버넌스(GovValidator) 제안을 통해 변경 가능함.

## 현상
- 다음 시나리오에서 트랜잭션이 처리되지 않는 문제가 발생함:

### 재현 시나리오
1. 초기 상태: gasTip = 27600 Gwei
2. 거버넌스 제안 → 30000 Gwei로 변경 (정상 반영)
3. 이후 27600 Gwei로 복원하기 위한 거버넌스 제안 트랜잭션 제출

### 결과
1. 해당 트랜잭션이 pending pool에 지속적으로 남아 있음
2. 블록에 포함되지 않으며 상태 변화 없음
3. 동일 조건에서 반복 재현 가능


## 통과 기준 유닛테스트 (수정 완료 시 반드시 통과)

### 테스트 목적

  GasTip 거버넌스 제안 실행 후, 변경값이 제안 포함 블록(N)이 아닌 N+1 블록부터 적용되는지 검증.
  GasTip 확인은 블록 헤더 extradata(WBFTExtra.GasTip) 에서 읽는다. 거버넌스 파라미터 조회 금지.

### 시나리오 (순서대로)

  1. 초기값 확인: 현재 블록 extradata → GasTip = 27600 Gwei
  2. 1차 제안: GasTip → 30000 Gwei 거버넌스 제안 생성 + 과반수 투표 → 제안 포함 블록 번호 = N 기록
  3. 변경 시점 검증:
    - Block N extradata → GasTip = 27600 Gwei (아직 미적용)
    - Block N+1 extradata → GasTip = 30000 Gwei (적용됨)
  4. 2차 제안 (원복): GasTip → 27600 Gwei 거버넌스 제안 생성 + 과반수 투표 → 제안 포함 블록 번호 = M 기록
  5. 원복 시점 검증:
    - Block M extradata → GasTip = 30000 Gwei (아직 미원복)
    - Block M+1 extradata → GasTip = 27600 Gwei (원복됨)

### Pass 조건

  - 두 제안 모두 생성·승인·블록 포함 성공
  - N/N+1, M/M+1 각각 위 값과 일치
  - Consensus error, chain halt, execution error 없음
