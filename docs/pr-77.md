
[StableNet] 거버넌스 GasTip 복원 제안 시 트랜잭션 Pending Pool 정체 이슈 원인 분석

## 설명

## 배경
- StableNet에서는 거버넌스를 통해 gasTip 값을 동적으로 변경할 수 있음.
- 기본값은 27600 Gwei이며, 거버넌스(GovValidator) 제안을 통해 변경 가능함.

## 현상
- 다음 시나리오에서 트랜잭션이 처리되지 않는 문제가 발생함:

### 재현 시나리오
1. 초기 상태: gasTip = 27600 Gwei
2. 거버넌스 제안 → 30000 Gwei로 변경 (정상 반영)
3. 이후 27600 Gwei로 복원하기 위한 거버넌스 제안 트랜잭션 제출

### 결과
1. 해당 트랜잭션이 pending pool에 지속적으로 남아 있음
2. 블록에 포함되지 않으며 상태 변화 없음
3. 동일 조건에서 반복 재현 가능


# 통과 기준 유닛테스트 (수정 완료 시 반드시 통과)

## 테스트 목적

거버넌스 제안을 통해 `GasTip` 파라미터를 변경한 후,
변경된 값이 **제안이 포함된 블록의 다음 블록(N+1)** 부터 정상 반영되는지 검증한다.

또한 변경된 값을 다시 원래 값으로 복구하는 거버넌스 제안을 수행하고,
동일하게 **다음 블록(N+1)** 부터 원복되는지 검증한다.

최종적으로 **상향 변경 → 반영 → 원복 → 반영** 전체 lifecycle 이 정상 동작해야 한다.

---

# 테스트 시나리오

## Step 1. 초기 GasTip 값 확인

현재 네트워크의 `GasTip` 기본값을 확인한다.

### 검증 항목

- 현재 블록 헤더의 extradata에서 WBFTExtra.GasTip 값 확인

### Expected Result

```text
GasTip = 27600 Gwei
```

---

## Step 2. GasTip 상향 거버넌스 제안 생성

`GasTip` 값을 `30000 Gwei` 로 변경하는 Governance Proposal Transaction을 생성하고 네트워크에 제출한다.

### 수행 항목

- Proposal Transaction 생성
- Transaction 전송

### Expected Result

- Proposal 생성 성공
- Proposal 상태 Pending 등록

---

## Step 3. Validator 투표 진행

Validator 노드들이 Proposal에 대해 투표를 수행한다.

### 수행 항목

- Validator vote 실행
- 과반수 이상 승인

### Expected Result

- Proposal 승인 성공
- Proposal execution transaction 생성

---

## Step 4. Proposal 트랜잭션 블록 포함 확인 (Block N)

Proposal execution transaction이 블록에 포함되는지 확인한다.

### 수행 항목

- Proposal 포함 블록 번호 기록

### Expected Result

```text
Proposal execution transaction included in Block N
```

---

## Step 5. Block N 시점 GasTip 확인

Proposal이 포함된 Block N의 extradata에서 GasTip이 기존 값을 유지하는지 확인한다.

### 수행 항목
- Block N 헤더의 extradata에서 WBFTExtra.GasTip 값 읽기

### Expected Result

```text
GasTip = 27600 Gwei
```

---

## Step 6. Block N+1 에서 변경값 반영 확인

다음 블록 생성 후 Block N+1의 extradata에서 변경된 GasTip 값을 확인한다.

### 수행 항목

- Block N+1 생성 대기
- Block N+1 헤더의 extradata에서 WBFTExtra.GasTip 값 읽기

### Expected Result

```text
GasTip = 30000 Gwei
```

---

## Step 7. GasTip 원복 거버넌스 제안 생성

`GasTip` 값을 다시 `27600 Gwei` 로 변경하는 Governance Proposal Transaction을 생성하고 제출한다.

### 수행 항목

- Proposal Transaction 생성
- Transaction 전송

### Expected Result

- Proposal 생성 성공
- Proposal Pending 상태 등록

---

## Step 8. Validator 투표 진행

Validator가 원복 Proposal에 대해 투표를 수행한다.

### 수행 항목

- Validator vote 실행
- 과반수 승인 확보

### Expected Result

- Proposal 승인 성공
- Proposal execution transaction 생성

---

## Step 9. Proposal 트랜잭션 블록 포함 확인 (Block M)

원복 Proposal execution transaction이 블록에 포함되는지 확인한다.

### 수행 항목

- Proposal 포함 블록 번호 기록

### Expected Result

```text
Proposal execution transaction included in Block M
```

---

## Step 10. Block M 시점 GasTip 확인

Proposal이 포함된 Block M의 extradata에서 GasTip이 이전 값을 유지하는지 확인한다.

### Expected Result

```text
GasTip = 30000 Gwei
```

---

## Step 11. Block M+1 에서 원복 확인

다음 블록 생성 후 원래 값으로 복구되었는지 확인한다.

### 수행 항목

- Block M+1 생성 대기
- Governance parameter 재조회

### Expected Result

```text
GasTip = 27600 Gwei
```

---

# 최종 통과 기준 (Pass Criteria)

다음 조건을 모두 만족해야 테스트 통과로 판단한다.

## Governance 처리 검증

- [ ] 첫 번째 Proposal 생성 성공
- [ ] 첫 번째 Proposal 투표 및 승인 성공
- [ ] 첫 번째 Proposal execution transaction 블록 포함 성공

- [ ] 두 번째 Proposal 생성 성공
- [ ] 두 번째 Proposal 투표 및 승인 성공
- [ ] 두 번째 Proposal execution transaction 블록 포함 성공

## Parameter 변경 시점 검증

- [ ] Block N 에서는 기존 값 유지 (`27600 Gwei`)
- [ ] Block N+1 에서 변경 값 적용 (`30000 Gwei`)

- [ ] Block M 에서는 기존 값 유지 (`30000 Gwei`)
- [ ] Block M+1 에서 원래 값 적용 (`27600 Gwei`)

## 안정성 검증

- [ ] Consensus error 없음
- [ ] Chain halt 없음
- [ ] Execution error 없음
- [ ] State inconsistency 없음
